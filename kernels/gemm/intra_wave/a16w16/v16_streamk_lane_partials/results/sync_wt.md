# v16_streamk_lane_partials: write-through partials with relaxed flags (2026-10-08)

Before: write-through (`.wt`) partials, then the compiler's GPU-scope release on the flag or barrier arrival and an acquire after the wait (`buffer_wbl2 sc1`, `buffer_inv sc1`).
After: the same `.wt` partial stores and drain in every wave, then relaxed `gpu`-scope flags and counters, and `.cv` partial reads behind a compiler fence ([memory_model_litmus WRITEUP](../../../../../../experiments/memory_model_litmus/WRITEUP.md), recommendation 1).

GPU 0, Triton v2.2 + deepbind shim, llirSched plugin, **without the amdgcnas hook** (`TRITON_AMDGCNAS_PLUGIN` unset). Old and new code were measured on the same day with the same commands, in two interleaved rounds. Raw tables: [results/sync_wt](../../v21_streamk_l2_partials/results/sync_wt/); generated by `v21_streamk_l2_partials/sync_wt_compare.py`. Numbers in earlier WORKLOG entries were taken on another GPU with the amdgcnas hook, so compare only within this file.

## Correctness

- `check_streamk.py`: 36 configurations (the 9 stream-K shapes, both tile orders, with and without bias, 30 rotating launches each), no wrong result, every flag re-armed.
- `experiments/streamk_split_count/check_all.py` (`STREAMK_NUM_PROGRAMS` = S, 2 S and all): 24 configurations, all pass.
