## Summary

A study of the a16w16 v9 kernel (`a16w16/v9_beyond_hotloop`, fp16) on a skinny shape, **M×N×K = 256×65536×8192**, on MI355X (gfx950). Closed out on 2026-10-17.

- A **power model predicts every workgroup layout within ~1%**.
- The shipped v9 runs **4.8% below its power roof**, limited by its memory path.
- With **non-temporal B** (`cache_modifier=".cs"` on B's `buffer_load_to_shared`), v9 reaches **1,214–1,226 TFLOPS** and sits on the power roof. hipBLASLt gets **1,186–1,188**.
- At the 1,400 W socket cap, the kernel is **bandwidth-bound below M≈165 and power-bound above**. The MFMA peak never binds.

## Setup

- gfx950-gluon-tutorials `main` 32418e5, Triton `gfx950-tutorial-v3.0` (3b0c7f081), MI355X.
- Numbers are sustained rates from rocprofv3 kernel traces. In-loop efficiency comes from ATT.
- NT-B runs are built without the amdgcnas plugin, which can't assemble instructions with two cache-policy bits ([gfx950-gluon-tutorials#67](https://github.com/ROCm/gfx950-gluon-tutorials/issues/67)).
- K is 8192 because 256×65536×65536 crashes: B is 8 GiB, and the kernel's buffer offsets are 32-bit (4 GiB limit).

## Findings

### 1. Why the skinny shape is slower

| | Skinny (256×65536) | Square |
|---|---|---|
| Memory latency | **1,915 cycles** | 740 cycles |
| L2 hit rate | **48%** | 80% |

B has no reuse, so every K-step pulls 8 MiB of B from HBM. Every alternative XCD mapping tried was slower or neutral.

### 2. The shipped kernel is bound by its load stream

- With LDS reads and MFMAs removed, the loads-only kernel runs at almost full-kernel speed: **1,192 vs 1,179 TFLOPS**, even though its clock is much higher (**2,347 vs 1,425 MHz**). Loads-only with NT B reaches **1,514**.
- Skipping A's loads helps the skinny shape by 9.2% and the square shape by 7.0%, so most of that gain isn't specific to the skinny shape. The idea that A's L2 hits crowd out B's misses is mostly not supported.
- NT loads leave the L2 hit rate unchanged, but they cut L2 tag stalls.

### 3. Bandwidth, from spec to kernel

| Step | TB/s |
|---|---|
| Spec | 8.19 |
| Pure read | 6.57 |
| Default caching | 5.61 |
| Loop, B loads only | 5.21 |
| + A loads | 4.70 |
| + compute (shipped v9) | 4.57 |

For B's access pattern, a pure-read probe gets **6.68–6.82 TB/s** with NT. The same bytes read contiguously get 7.16 TB/s.
- The 128 B piece per row costs bandwidth under default caching, but not under NT.
- Under NT, the remaining ~7% comes from reading 256 separate regions at once.

### 4. NT B helps the skinny shape but not the square one

- **Skinny:**
  - v9 gets 1,134–1,185 TFLOPS; it settles in one of two modes per process.
  - v9 + NT B gets **1,214–1,226** at 1.44 GHz and 4.91–5.06 TB/s, with in-loop efficiency of 94.5–95.7% in ATT.
  - hipBLASLt gets 1,186–1,188.
- **Square, 4096³:** the L2 hit rate doesn't change, but HBM bytes go up **1.34–2.29×**, because NT misses aren't shared through the Infinity Cache. Sustained TFLOPS are 1,397 / 1,396 / 1,375 / 1,365 for default / NT A / NT B / NT both.
- **M=512:** compute-bound inside the loop: 1,365 TFLOPS at 1,553 MHz, against 1,137 for hipBLASLt.

### 5. Power sets the clock

- The power limit is the **1,400 W** socket cap, which is already at its maximum. Memory and fabric clocks each have one level, so only the GFX clock throttles. None of these limits can be raised.
- For M=256, the power roof (**1,220 TFLOPS**) is well below the bandwidth roof (**1,635**).
- Short GPU-side spacers show the two regimes:
  - NT B is power-bound: +9% clock gives +11% speed.
  - The shipped kernel is memory-bound: +8% clock gives +2–5%.
- Loaded latency rises from **514 ns** unloaded to **~1,010 ns** at the roof. Fewer CUs, each holding more in flight, see higher latency.

### 6. Workgroup layouts

| Layout | TFLOPS |
|---|---|
| 1×256 | 1,174 |
| 1×256 + NT B | 1,212 |
| 2×128 | 1,353 |
| 4×64 | 1,450 |
| 8×32 | 1,486 |
| 16×16 | 1,480 |

- Sharing happens per XCD, and the L2 hit rate follows **1 − (m+n)/64**.
- The Infinity Cache serves data that several XCDs read.
- The clock rises as HBM traffic falls.
- The power model predicts each layout within ~1%.

### 7. The tutorial's 98% is real, not an ATT artifact

- **Square shape:** whole-dispatch cycles barely change with clock (+1.4%), so the 98% holds. The skinny shape pays +7–11%.
- **Clock-corrected in-loop efficiency:** ~84% for shipped v9, 88% with NT B, and ~95% for 2×128 and squarer layouts.
- **Upstream main (2122e24ef):** the tutorial perf table is at parity with v3.0: llir ~95.5–96%, llir+amdgcnas ~98%, 1,563–1,583 TFLOPS.
